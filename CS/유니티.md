# 오브젝트 풀링
- 정의: 잦은 객체 생성(Instantiate)과 파괴(Destroy)로 인한 GC 발생 및 CPU 과부하를 최소화하기 위해, 객체를 풀(Pool)에 미리 만들어 두고 재사용하는 기술
- 핵심 원리: Destroy 대신 SetActive(false)로 꺼서 반납하고, 필요할 때 SetActive(true)로 켜서 대여

# 오브젝트 풀링의 한계점 및 해결책
- **문제점:** 게임 시작 시점에 풀링할 오브젝트가 너무 많으면, 초반 **메모리 점유율이 폭발적으로 상승**하고 **초기 로딩 시간**이 길어짐
- **해결책:** 유니티 내장 `UnityEngine.Pool` API를 활용하여, 초기에는 최소 수량만 생성한 뒤 풀이 모자랄 때만 유동적으로 확장하고, 최대 크기를 초과하여 반납되는 객체는 자동으로 `Destroy`

# 유니티 AI 몬스터 구현 과정

**1. 몬스터 생성**  
- Monster Prefab 구성
  
**2. 플레이어 감지**  
- 플레이어를 AI의 Target으로 설정
  
**3. AI 의사결정**  
- 몬스터 행동이 단순하고 상태 간 전환이 명확하면 State Machine 사용
- 행동과 조건이 복잡해질 경우 Behavior Tree로 우선순위와 조건을 계층적으로 관리
 
**4. 플레이어 추적**  
- Chase 상태에서 Target의 위치 확인
- Pathfinding을 통해 이동 경로 계산
- 단순한 환경 -> 직접적인 방향 이동으로 구현, 맵의 복잡도가 증가하거나 장애물을 우회해야 하는 경우 -> NavMesh 기반 경로 탐색을 적용

**5. 공격**  
- 공격 범위 진입 여부 확인 및 공격

**6. 상태 전환**  
- 플레이어와의 거리, 체력 등의 조건에 따라 AI 상태를 전환

**7. 사망 및 정리**  
- HP가 0이 되면 Dead 상태로 전환
- 몬스터 제거 또는 Object Pool 반환
