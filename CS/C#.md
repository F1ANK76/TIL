# 참조 타입 (string, object 등)
- **정의:** 참조 타입(Reference Type)이며 매니지드 힙(Managed Heap) 메모리에 할당되고, 한 번 생성되면 값을 변경할 수 없는 불변(Immutable)의 특징을 가집니다.
- 문제: 문자열을 수정하거나 합산할 때마다 매번 새로운 문자열 객체가 힙에 생성되므로 이전 데이터들이 가비지로 쌓여 잦은 GC 렉을 유발합니다.
- 해결: 유니티 기준, 내부에 가변 배열 구조를 가진 `StringBuilder`를 활용하여 버퍼를 통해 문자열 연산 시 발생하는 가비지 생성을 방지합니다.
- 추가 정보: `StringBuilder` 자체를 매번 `new`로 생성하면 이 또한 가비지가 되므로, 클래스 멤버 변수로 캐싱하여 `Clear()`로 내부 버퍼만 초기화해 재사용해야 완벽한 최적화(Zero-Alloc)가 가능합니다.

# 값 타입 (int, bool 등)
- **정의:** 변수가 주소값을 가지지 않고, **스택(Stack) 메모리**에 데이터 값을 직접 저장하는 타입입니다.
- 스택 오버플로우 : 함수가 끝없이 자기 자신을 호출하는 **무한 재귀 함수(Infinite Recursion)** 상황에서 스택 프레임이 계속 쌓이다가 공간이 고갈되어 발생합니다.

# virtual / abstract / interface 차이

- **virtual**: 부모의 기본 구현을 쓰면서 자식이 일부만 커스텀할 때 사용
- **abstract**: 부모에 기본 구현이 없고, 자식이 각자 전부 구현해야 할 때 사용
- **interface**: 부모 클래스와 무관하게, 구현 없이 할 수 있는 일의 규격만 정할 때, 한 클래스가 여러 역할을 동시에 가져야 할 때 사용
