# String
- 정의: 참조 타입(Reference Type)이며 매니지드 힙(Managed Heap) 메모리에 할당되고, 한 번 생성되면 값을 변경할 수 없는 불변(Immutable)의 특징을 가집니다
- 문제 : 문자열을 수정하거나 합산할 때마다 기존 데이터가 수정되는 것이 아니라, 매번 새로운 문자열 객체가 힙에 생성되므로 이전 데이터들이 가비지로 쌓여 잦은 GC 렉을 유발
- 해결 : 유니티 기준, 내부에 가변 배열 구조를 가진 StringBuilder를 활용하여 버퍼를 통해 문자열 연산 시 발생하는 가비지 생성을 방지
- 추가 정보 : StringBuilder 자체를 매번 new로 생성하면 이 또한 가비지가 되므로, 클래스 멤버 변수로 캐싱하여 Clear()로 내부 버퍼만 초기화해 재사용해야 완벽한 최적화(Zero-Alloc)가 가능

# OOP
- 정의: 프로그램을 '객체'라는 독립된 단위들로 쪼개고, 이 객체들의 상호작용으로 구현하는 개발 패러다임
- 캡슐화: 변수를 변형하는 로직과 데이터를 하나로 묶고, 외부 접근을 제한(private)하여 데이터 오염을 방지
    - **예시:** 플레이어의 `meso` 변수를 외부에서 직접 수정하지 못하게 `private`으로 막고, `GainMeso()` 메서드로만 접근

- 상속: 부모 클래스의 기능을 자식 클래스가 물려받아 코드 중복을 제거하고 재사용
    - **예시:** 부모 `Item` 클래스를 상속받아 `Equipment`, `UseItem` 자식 클래스를 만듦

- 다형성: 하나의 메서드나 클래스가 상황(오브젝트 타입)에 따라 여러 가지 형태(기능)로 동작하는 성질 (Virtual, Override 활용)
  - **예시:** 부모 `Item` 클래스를 상속받아 `Equipment`, `UseItem` 자식 클래스를 만듦

- 추상화: 복잡한 내부 구현은 숨기고, 인터페이스나 추상 클래스를 통해 핵심적인 규칙(껍데기)만 정의하는 것
  - **예시:** 부모 `Item` 클래스를 상속받아 `Equipment`, `UseItem` 자식 클래스를 만듦
